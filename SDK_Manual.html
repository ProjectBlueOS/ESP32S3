Lifecycle & Language

:onDraw Rendering loop — use all Graphics.* commands here
:onUpdate Logic loop — runs before draw
:onMouseEvent Sets event_type, event_x, event_y
:onKeyboardEvent Sets event_type, event_value 
# Variables & Expressions
LET x = 10, y = 20, z = 30           # multi-LET
LET label = "Heap: " + mem_free + " B" # string concat
LET blink = (second + (minute * 60)) % 2 # parentheses + nested math

IF (score + bonus) > 100 THEN
  IO.PRINT "High score!"
ENDIF
FOR i = 0 TO 10 STEP 2
  Graphics.DrawCircle 200, 150, i * 5, CYAN
NEXT

Operators: + - * / % ( ) — the + operator auto-concatenates when either side is a string. Expressions now support nested parentheses and unary negation (e.g. -(x + 5)).

Syntax Best Practices

For maximum stability and performance, follow these guidelines:

  • One Command Per Line: High-density scripts (using : for multi-command lines) are deprecated. Use individual lines for each command.
  • PSRAM Optimization: The interpreter automatically places strings, lines, and variable maps in PSRAM. No manual memory management is required.
  • Explicit Parentheses: While operator precedence is supported, use parentheses for complex 3D or physics math to ensure predictability.

Coordinate System

Content-Area Coordinates

All drawing and input coordinates use the content area as their origin. The engine automatically handles the window border (2px) and titlebar (30px) offsets. Scripts should treat (0, 0) as the top-left corner of the drawable area.

Property Value Description
Origin (0, 0) Top-left of the content area (below titlebar, inside border)
Content Width 396 px Window width (400) minus 2px border on each side. Available as win_w
Content Height 318 px Window height (350) minus titlebar (30) and border (2). Available as win_h
Clipping Automatic Drawing outside the content area is clipped — no pixels leak into borders or titlebar 
# Clear the full content area
Graphics.FillRect 0, 0, 396, 300, BLACK

# Draw at content origin — no manual border offsets needed
Graphics.DrawString 10, 10, "Hello!", CYAN

# Mouse events also use content-area coordinates
:onMouseEvent
  # event_x=0 means left edge of content, event_y=0 means top of content
  Graphics.FillCircle event_x, event_y, 5, RED
RETURN

Note: The variables win_w and win_h are automatically set each frame and reflect the usable content dimensions. Use these instead of hardcoded values for portable scripts.

SYSTEM.PING NETWORK

Sends ICMP echo request via esp_ping. Supports hostnames and IPs.
SYSTEM.PING "google.com"
IF ping_success = 1 THEN
  Graphics.DrawString 10, 10, "RTT: " + ping_ms + "ms", 0x07E0
ENDIF
→ ping_success (0/1), ping_ms (round-trip ms)

SYSTEM.WGET NETWORK

Downloads a file over HTTP/HTTPS with TLS via esp_http_client.
SYSTEM.WGET "https://example.com/data.json", "/downloads/data.json"
IF wget_success = 1 THEN
  IO.PRINT "Got " + wget_size + " bytes"
ENDIF
→ wget_success (0/1), wget_size (bytes)

Network.SendEmail NETWORK

Sends an email via the system's QMail SMTP engine. Only 3 arguments are required — the system automatically uses the SMTP credentials from config.txt on your SD card. You can optionally override the server, port, and password for one-off sends to a different provider.
# Minimal usage — uses config.txt credentials automatically
Network.WaitConnected
Network.SendEmail "to@example.com", "Subject", "Hello from BlueScript!"

# Advanced usage — override SMTP server for this send only
Network.SendEmail "to@example.com", "Alert", "Body text", "smtp.other.com", 587, "app_password"
Argument Type Required Description
to String ✓ Recipient email address
subject String ✓ Email subject line
body String ✓ Message body text
server String SMTP server address (default: from config.txt)
port Integer SMTP port — 465 (SSL) or 587 (STARTTLS)
password String SMTP App Password (default: from config.txt)

config.txt SMTP Setup

Place a config.txt file in the root of your SD card with the following fields. The system reads these at boot and uses them as defaults for all Network.SendEmail calls. 

SSID: YourWiFiName
PW: YourWiFiPassword
EMAIL: you@gmail.com
MAIL_SERVER: smtp.gmail.com
MAIL_PORT: 465
MAIL_PW: your_app_password
MAIL_USER: you@gmail.com

Note: For Gmail, generate an App Password in your Google Account security settings and use it as MAIL_PW. The MAIL_USER field is optional — if omitted, EMAIL is used as the login username.

File System IO

All operations set io_success to 1 (OK) or 0 (fail).
Command Arguments Description
IO.MKDIR "path" Create directory
IO.REMOVE "path" Delete file/directory (recursive)
IO.RENAME "old", "new" Rename or move
IO.COPY "src", "dest" Copy a file
IO.EXISTS "path" Check existence
IO.Zip "source", "output.zip" Compress a file or directory into a ZIP archive (async)
IO.Unzip "archive.zip", "dest_dir" Extract a ZIP archive to a directory (async)
IO.PRINT "message" Log to system console 
IO.MKDIR "/backups"
IO.COPY "/data.bb", "/backups/data.bb"
IF io_success = 1 THEN
  IO.PRINT "Backup created"
ENDIF

# Zip a directory and unzip it elsewhere
IO.Zip "/scripts", "/scripts.zip"
IO.Unzip "/scripts.zip", "/restored"

Note: IO.Zip and IO.Unzip run asynchronously in background tasks. They support both individual files and entire directories recursively. The operations use cooperative SD card locks with minizip I/O to guarantee thread-safe execution without causing watchdog crashes or SD corruption.

Sprite System NATIVE

Up to 16 cached sprite slots. Images loaded once into PSRAM, drawn at hardware speed. The engine uses a PSRAM-backed memory model for scripts and variables, allowing 1000s of variables without impacting internal SRAM.

Command Arguments Description
Sprite.Load id, "path" Load image into slot 0–15
Sprite.Draw id, x, y Draw at position
Sprite.DrawScaled id, x, y, scaleX, scaleY Draw with scaling
Sprite.GetSize id Sets sprite_w, sprite_h 
Sprite.Load 0, "/sprites/player.png"
Sprite.Load 1, "/sprites/enemy.png"

:onDraw
  Sprite.Draw 0, playerX, playerY
  Sprite.DrawScaled 1, enemyX, enemyY, 2.0, 2.0
RETURN
